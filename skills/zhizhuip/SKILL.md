# 蜘蛛 IP

帮助用户把需求落实为蜘蛛 IP 产品选择、代理连接配置和账号操作。需要客户端已经连接蜘蛛 IP 的本地 stdio MCP 服务，通常配置名为 `zhizhuip`。

## 执行方式

1. 从用户需求和上下文确定任务、产品及操作对象。已有信息足够时继续；产品或目标账号仍有歧义时，只询问影响本次操作的缺失信息。
2. 检查当前客户端实际暴露的蜘蛛 MCP 工具。以工具 schema 为准填写参数；工具名前可能有客户端添加的命名空间。文档中的名称用于定位工具，不能当作工具已连接的证据。
3. 未连接 MCP 时，引导用户按[仓库安装说明](https://github.com/Lianzhou-Information-Technology-Co-Ltd/zhizhuip-agent-tools#一次安装-skill-与-mcp)在本机通过 `install` 入口安装 Skill 和 MCP，或手动配置 `zhizhuip` 服务及 `ZHIZHUIP_TOKEN`。不要假定系统已全局安装 `zhizhuip-agent-tools` 命令。统一安装的启动器可从私有凭证文件读取 API Key，不要求在客户端配置中重复写 Key。不要索要网站登录密码或要求把完整 Key 发到对话中。连接缺失时可以提供产品说明，不能声称已查询账号或执行操作。
4. 优先使用用户指定的已有账号。获取代理配置不自动购买产品或创建子账号。需要变更时先列清实际对象、参数、费用依据和影响，再走 MCP 确认流程。
5. 依据实际返回结果报告完成情况。批量任务分别列出成功、失败和结果未知的对象；分页查询只覆盖部分数据时，注明范围。

## 关键约束

- 各产品支持的工具不同。不要将未暴露的后端接口、网站功能或其他产品工具当作当前可调用能力，也不要自行直连 HTTP 来绕过 MCP。
- Skill 不替代接口鉴权和用户授权。收到 `confirm_token` 后等待用户明确同意，再用相同业务参数重调；静默期结束不是授权。用户明确拒绝时停止，不重试确认码，不主动启用 `--yes`。
- 收费或删除操作出现超时、连接中断时，保留结果未知状态，先查证再决定后续动作。不能把请求失败直接解释为业务未执行。
- 修改备注、间隔、流量限制或账密前，必须读取[子账号管理](references/account-lifecycle.md)中的配置副作用。当前后端会补发默认协议等配置；用户只授权改一项且要求保留其他配置时，不能直接执行。
- 返回 `code=1` 仍要检查 `msg`、批量失败明细和查询结果；删除可能返回“删除失败”，限流批量可能部分失败，不以成功标记推断全部完成。
- API Key、代理密码和切换 token 不写入日志、公共文档或示例仓库。用户要求连接配置时，仅使用本次所需账号的凭证；普通账号列表默认不展开密码。
- 将“配置已生成”“管理接口查询成功”和“实际代理连通测试成功”分开表述。未进行代理请求时，不宣称代理已经可用；未明确取得费用时，不给出确定报价。
