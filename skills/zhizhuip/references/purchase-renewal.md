# 购买、续费与退单。

适用于用户要求购买产品、续费账号、升级带宽或申请退单的场景。先读取当前 MCP 工具的参数说明和产品枚举；下面的流程不代替工具校验，也不保证库存、价格或操作资格保持不变。

## 先确定产品与操作对象。

| 产品 | 购买与续费方式 | 关键区别 |
| --- | --- | --- |
| `dynamic-no-expiry`、`dynamic-monthly` | 使用 `order_buy_dynamic` 购买流量。 | `num` 单位为 GB，整数 1–5000；期限流量当前仅 30 天，`bill_timelen=1`，省略也默认 30 天；永久流量不传期限。不要套用静态子账号续费工具。 |
| `static-standard`、`static-native`、`static-isp-native` | 使用 `order_buy_time_ip` 购买，使用 `order_renew` 续费。 | `num` 为 IP 数量；续费内容按国家分组，明确是否连同附加带宽续费。 |
| `static-ipv6` | 使用 `order_buy_ipv6` 购买，使用 `order_renew_ipv6` 续费。 | 使用专用工具及其参数，不能照搬其他静态产品的完整配置。 |
| `datacenter` | 使用 `order_buy_time_ip` 购买，使用 `order_renew` 续费。 | 单笔购买最多 50 个，不支持 7 天购买档，也不套用静态住宅的附加带宽功能。 |
| `dynamic-bandwidth` | 使用名称含 `dynamic_bandwidth` 的专用购买、续费、升级和退单工具。 | 按带宽与时长计费；新购一次创建一个子账号，最低 10 Mbps，入口国家为 US、DE、SG。 |

子账号编号按字符串传递。动态带宽的 `sub_account_id` 必须取 `sub_account_list` 返回的 `rows[].sub_account`，不能使用同一行的本地 `id`；其他产品按对应工具说明选择 `id` 等字段。

动态带宽购买和续费的 `timelen` 为 1、2、3，分别表示 30、90、180 天；普通时长 IP 的期限枚举包含更多档位。不要跨产品复用期限编号。带宽升级参数表示升级后的总带宽，例如从 10 Mbps 升到 20 Mbps，应填写 20。

## 查询并形成操作方案。

1. 从用户请求中确定产品、国家、数量、期限、协议和目标账号，只补问缺失且影响结果的信息。用户只要求报价或分析时，完成查询后停止。
2. 续费、升级和退单先用 `sub_account_list` 核实账号归属、产品、当前状态及操作对象。明确分页覆盖范围；动态带宽还需检查 `can_renew`、`can_upgrade` 和 `refunding` 等相关字段。
3. 按产品查询 `user_price`、`user_balance`、`coupon_list`、地区和库存。优先使用当前账号价格；`official_price` 是官网标价，不能直接当作账号成交价。`ip_range_status` 仅覆盖其产品枚举中的静态住宅产品，不能推定其他产品已有库存查询。
4. 展示具体目标、数量、期限、协议、带宽、优惠券选择，以及预计费用的来源。动态流量按整单数量档位计价，不能用首档单价推算所有数量；若价格响应不足以覆盖选中档位，先在网站核实。计算依据不足时不编造金额、折扣或券适用条件。
5. 按下面的确认流程执行。成功后报告实际返回结果，并在请求范围内查询相关账号状态；缺少可用核对工具时说明尚未核实的内容。

普通时长 IP 续费通过 `content` 按国家组织账号，一次最多 200 个。批量超过限制时先说明拆分范围；每个实际写操作仍需单独确认。不要为了凑齐批次扩大用户选择的账号范围。

## 优惠券与期限参数。

`coupon_list` 使用其正式参数 `type/status`，不接收 `product`：动态流量为 `0/0`，静态住宅时长为 `1/1`，数据中心为 `2/1`。返回券标识是 **`conpon_id`**，不是 `id`，传给支持优惠券的下单或续费工具时转成 schema 要求的整数。字段拼写遵循现有接口，不改成 `coupon_id`。结果中缺标识或金额门槛不清时先核实，不补猜。

列表中出现券不等于本单必然适用；核对产品、门槛、期限及与自定义价的关系，最终以后端判定为准。IPv6 购买及续费不接收优惠券。动态带宽适用券目前需在网站核实，不拿 `type=0,status=0` 的流量券直接代用。

例如，用户已核实费用，选择券 `conpon_id=27`，购买 1 个美国非原生静态住宅 IP、30 天、SOCKS5，首次调用 `order_buy_time_ip` 的参数如下。它只发起确认预览，不能把示例券或用户尚未回复的确认码当成授权：

```json
{"product":"static-standard","country":"US","num":1,"timelen":1,"agree":"SOCKS5","conpon_id":27}
```

真实调用仍以当前工具 schema 为准；`timelen` 是期限、`agree` 是协议，字段名不能自行翻译。取得确认后才用原业务参数附上工具返回的 `confirm_token`。

普通时长 IP：0=7 天、1=30 天、2=90 天、3=180 天、4=360 天；数据中心购买不能用 7 天。IPv6 购买有 7 天档，续费仅 1–4，无 7 天档。动态带宽仅 1–3。不要给专用 IPv6 或动态带宽工具额外传 `product`。

静态住宅 IPv4 新购最多 300 个，数据中心最多 50，IPv6 最多 5000。普通新购指定 `specifyIps` 时各段数量之和必须等于 `num`；使用当前库存查询的段。`verder_order_id` 是外部请求订单标识，其缓存行为不等于永久幂等；结果未知时保留原请求信息先核对，不能换一个 ID 盲目再下单。

## 测试 IP 与缺货预约。

`order_buy_test_ip` 用于静态住宅 IPv4 或数据中心。它会扣账户余额并占用当月测试额度，不能当免费试用，也不能为用户的“看看是否有货”自动调用。数量为 1–100，国家用编码、协议必填；测试价取账号配置，普通价格不能代替测试价格。有效期由后台测试期限配置决定，不能保证固定 1 天。

当前 MCP 无专门测试价、剩余额度查询；先在网站核实金额、期限和额度，再按实际数量确认。本月已删除的测试账号仍计入额度；当前源码在本次数量 **大于或等于** 剩余额度时都会拒绝，不承诺“恰好用完”能通过。失败后不自动换数量下单。

`ip_booking` 用于静态住宅 IPv4 和数据中心的缺货需求，数量 1–1000，`country` 填国家名称，如“美国”。确认后提交预约记录及后台待办，不扣费、不生成子账号、不锁定库存，不保证补货日期。成功仅报告“预约已提交”；目前无进度查询工具，需要在网站或客服核实进展，不把预约后查到的旧账号当成新分配 IP。

## 静态带宽升级。

仅三种静态住宅 IPv4 产品使用 `order_bandwidth_upgrade`。先用 `sub_account_list` 查当前带宽、到期时间，用 `bandwidth_detail` 查已有带宽权益，用 `bandwidth_package_list` 按产品、国家查可选档位。

`bandwidth_num` 填升级后的总 Mbps，必须大于现有带宽；`sub_accounts` 是字符串 ID 数组，单次最多 200 个。有账号过期时先解决续费，不能在一次升级请求中顺带续费。实际差价按剩余有效时间和已有带宽权益计算，套餐目录价不是该账号的准确升级费；当前 MCP 没有试算工具，准确金额先在网站核实。确认后执行，再查账号和带宽详情；详情有 120 秒缓存，不高频轮询，也不把缓存旧值当成确定升级失败。

## 动态带宽的能力边界。

当前 MCP 的 `user_price`、`official_price` 不包含动态带宽报价，也没有暴露该产品的专用报价或订单详情查询工具。即使后端存在相应接口，也不能在 Skill 中假设工具已经可用，或直接发送 HTTP 请求绕过 MCP。

购买、续费、升级前，由用户在网站核实费用及适用优惠券，再确认具体操作；最终扣款以接口实际返回为准。列表仅支持分页，不套用其他产品的搜索、备注、改密和流量限额工具。连接字段缺失时不要补造；应报告当前返回的信息不足。

## 取得真实确认后执行。

写工具的确认预览只展示动作和参数，不会自动查询价格或余额。涉及扣费时，先完成费用核对，再发起写操作的确认流程。不要通过 `--yes`、修改静默期或直接调用后端跳过确认。

- 客户端显示确认弹窗时，让用户核对并作出选择；助手不能代替用户接受。
- 工具返回“待确认，尚未执行”和 `confirm_token` 时，向用户转述操作预览并等待真实回复。用户明确同意后，才使用相同工具、相同业务参数和该确认码继续执行。
- 确认码绑定工具和参数，通常 5 分钟有效、只能使用一次；默认静默期为 10 秒。静默期结束只是时间条件满足，不代表用户已经同意。不得等待到期后自行重试，也不得循环试码。
- 用户拒绝、取消或未回复时，不执行。即使工具把未完成的弹窗转为确认码流程，已明确的拒绝仍然有效。
- 用户改变目标、数量、期限或其他参数后，重新形成预览并确认；确认码过期时也重新确认。一次同意不授权后续重复操作。

## 根据结果结束或继续核对。

“待确认”不表示购买完成。只有实际执行结果才能作为操作成功的依据；不要把工具正常返回文本误判为业务成功。

退款申请成功表示进入平台审核，不表示余额已经退回。动态带宽使用 `order_refund_dynamic_bandwidth_apply`；普通 `order_refund_apply` 仅适用于其枚举列出的静态住宅产品。已有审核中的申请不重复提交。

普通静态住宅申请前核对下单时间和状态：当前限制下单后 1 天内，已续费、有进行中的带宽升级等情况不符合条件，最终以后端校验为准。传所选账号的 `id` 和用户提供的原因 `remark`。动态带宽使用业务 `sub_account_id`，先核对 `refunding` 等字段；不能把普通静态的 1 天规则扩展成其他产品已保证的资格。数据中心及 IPv6 当前无退单工具。

扣费操作超时、连接中断或响应无法解析时，结果可能未知。先核对账号、余额及网站订单记录；没有足够证据时向用户说明无法确认是否成功，不盲目重试购买、续费、升级或退单，也不把短时防重复机制当作完整幂等保证。
